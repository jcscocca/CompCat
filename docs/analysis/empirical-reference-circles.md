# Empirical reference-circle comparison

**Status:** implemented methodology (2026-07-30). This is the current single-place comparator
in the detailed Analyze view, assistant explanation, and run-scoped analytical CSV. The
implementation lives in `app/analysis/reference_circles.py`; the versioned center frame lives
in `app/data/seattle_street_segment_midpoints_v1.{csv,json}` and is regenerated by
`scripts/generate_reference_centers.py`. The former polygon-density baseline remains in the
API payload during validation, but current user-facing single-place comparisons do not read
it. User-selected place-vs-place inference remains a separate method documented in
[the pairwise comparison engine](pairwise-comparison-engine.md).

## Decision summary

CompCat should be able to answer:

> Under the selected radius, date range, layer, and filters, how does the reported-incident
> count around this location compare with the counts around comparable locations in the same
> geographic context?

The proposed method builds an **empirical reference distribution of equal-radius circles**:

1. Keep the observed incident locations fixed.
2. Define a finite set of eligible comparison centers, initially street-segment midpoints.
3. Put the user's same-radius circle at each comparison center.
4. Apply the identical date range, data layer, offense filters, and coordinate rules.
5. Compare the selected location's count with the distribution of those reference counts.

MCPP, sector, and city polygons define **where comparison centers come from**. They do not
imply that reported incidents are uniformly distributed inside a polygon, and they do not
provide an expected count by area. When the target circle intersects multiple MCPPs, the
reference distribution is a mixture weighted by the target circle's overlap with each MCPP.

The result is descriptive: a median, percentile range, and shares of comparison circles with
fewer, equal, or more reports. It is not a safety score, an individual-risk estimate, a
forecast, or—without a separately justified randomization model—a significance test.

## 1. Why change the comparator?

The live rest-of-area method compares the selected buffer's incident density with the density
of the surrounding MCPP or beat. That comparison is arithmetically consistent, but its
interpretation assumes the polygon-wide average density is a meaningful counterfactual for the
selected buffer.

Reported incidents are not evenly distributed within an MCPP. They cluster at micro-places,
along street networks, around activity nodes, and in relation to land use and reporting
behavior. A polygon average can therefore be dominated by places unlike the location the user
selected. The problem becomes more visible as the user increases the radius: the buffer
occupies more of the local polygon, crosses more boundaries, and leaves a changing
"rest-of-area" comparator.

Reference circles change the question. Instead of estimating what share of a polygon's reports
belongs in the target area, they measure what the observed map actually contains around many
other eligible locations. The target and every comparator use the same geometry. No report is
redistributed and no within-polygon uniformity assumption is required.

## 2. Formal definition

Let:

- `x₀` be the selected location;
- `r` be the selected radius;
- `B(x, r)` be the circle of radius `r` centered on `x`;
- `I(F, T)` be the observed incident points passing data-layer and offense filters `F` during
  inclusive date window `T`; and
- `S_g` be the finite set of eligible reference centers in geography `g`.

The count for any center `x` is:

```text
C(x; r, F, T) = Σ 1[distance(x, incident_i) ≤ r], for incident_i in I(F, T)
```

The target count is:

```text
C₀ = C(x₀; r, F, T)
```

The distance function and coordinate-eligibility rules must be identical to the detailed
Analyze view. In particular, a filter change changes the incident set but must not silently
change the eligible centers or comparison geography.

### 2.1 A single reference geography

For one geography `g`, the exact empirical cumulative distribution is:

```text
F_g(c) = (1 / |S_g|) · Σ 1[C(s; r, F, T) ≤ c], for s in S_g
```

This is a finite-population description of the observed map. If the service evaluates every
eligible center, there is no Monte Carlo sampling error and the method is not technically a
simulation.

### 2.2 Differential MCPP mixture at a boundary

Let `G` contain every MCPP polygon intersecting the target circle. For each MCPP `g`, calculate:

```text
a_g = area(B(x₀, r) ∩ g)
w_g = a_g / Σ_h a_h
```

The target's MCPP reference distribution is:

```text
F_MCPP(c) = Σ_g w_g · F_g(c)
```

Equivalently, a Monte Carlo draw first selects an MCPP with probability `w_g`, then selects an
eligible center uniformly from that MCPP. This is the **differential** part of the design: an
MCPP covering 70% of the target circle contributes 70% of the reference distribution, while
one covering 30% contributes 30%.

The circle around a sampled center is allowed to cross its MCPP boundary. Its count still uses
every qualifying observed incident within radius `r`. The MCPP controls the context from which
the center is selected; it does not clip or redistribute the circle's reports.

Some MCPP polygons overlap. In that case the areas above are membership weights, not a
partition of land. A center eligible under two MCPP components may contribute through both
components. That behavior is reproducible but must be disclosed and included in the boundary
sensitivity tests in §8.

Uncovered portions of the target circle must not be silently assigned to the nearest MCPP. The
payload should expose the covered-area share. If coverage or the number of eligible centers is
inadequate, the MCPP comparison is unavailable and the next broader geography becomes primary.

### 2.3 Sector and city reference distributions

The same construction applies at every level:

- **Sector:** select centers from the target sector, or use an overlap-weighted sector mixture
  when the target circle crosses sector boundaries.
- **City:** select from all eligible Seattle centers.

The method should return an interpretable geography ladder rather than force the polygon
average from one level to answer every question. MCPP is the preferred local context when
adequate; sector and city show how the same target sits in progressively broader contexts.

No literature-derived rule says that MCPP must disappear at exactly 1000 m. At 1000 m the city
comparison should always be available, but an adequate MCPP mixture may still be useful. A hard
radius cutoff, if later adopted, is a product rule that must be justified by the empirical
validation in §8 rather than presented as a statistical theorem.

## 3. Eligible comparison centers

The sampling frame is the method's most important design assumption. Sampling uniformly from
polygon area is rejected: it gives water, parks, industrial parcels, inaccessible land, and
ordinary addressable streets an arbitrary influence based only on land area.

### Implemented v1 frame: street-segment midpoints

V1 contains **23,793** half-length points from the City of Seattle Street Network Database
(SND), service item `783fd63545304bdf9d3c5f2065751614`. Eligibility is frozen in the
version metadata and generator:

```text
CITYCODE=1 AND ACCESS_CODE=1 AND ST_CODE IN (0,1,2) AND SEGMENT_TYPE=1
```

This selects open, public, inside-Seattle street segments. Generation then:

- uses the SND segment as the canonical unit;
- computes its half-line-length point in a local metric approximation;
- assign the midpoint to every reference polygon containing it; and
- records the source URL, source edit timestamp, row count, eligibility predicate, frame
  version, and CSV SHA-256 in the checked-in JSON metadata.

This frame gives every eligible street segment equal weight. It therefore supports the
interpretation "compared with a typical eligible street segment," not "compared with a typical
resident, business, visit, parcel, or square metre." Street segments have a strong
crime-and-place precedent, including Seattle-specific longitudinal work, but that precedent
does not make them the only defensible frame.

Two alternatives remain useful sensitivity checks for a future frame revision:

| Frame | What receives equal weight | Main limitation |
|---|---|---|
| Street-segment midpoints | Street segments | Long and short segments receive the same weight; road preprocessing matters. |
| Address points | Addressable locations | Apartment and commercial addressing conventions can strongly affect density. |
| Parcel centroids | Parcels | Large and small parcels receive equal weight; centroid may not represent access. |

The production method uses this one canonical frame. It does not switch frames by filter or
select whichever produces the most favorable comparison. A future frame revision must receive
a new version, retain sensitivity results, and must not silently reinterpret stored exports.

Future versions could stratify centers by a documented place type or land-use class, but only
if the classification is complete enough to avoid manufacturing a misleading
"like-for-like" claim.

## 4. Exact enumeration and Monte Carlo approximation

### 4.1 Prefer exact evaluation

If the number of eligible centers and incident-query cost are manageable, evaluate every
center and form the weighted empirical distribution exactly. Exact evaluation is deterministic,
contains no simulation noise, and makes repeated exports and UI views naturally agree.

### 4.2 Approximate only for performance

If exact evaluation is too expensive, approximate the mixture with reproducible Monte Carlo
draws:

1. Draw a geography component using its target-overlap weight.
2. Draw one center uniformly from that component's eligible frame.
3. Count incidents in the equal-radius circle.
4. Repeat until the requested precision or configured cap is reached.

The random seed must be derived from stable analysis inputs and the sampling-frame version, so
the same analysis produces the same result. Sampling should start with enough draws that a
worst-case 95% Monte Carlo margin for a reported share is no larger than about two percentage
points; 2,500 independent draws meet that approximation before finite-population corrections.
This is a computational-precision target, not evidence that the geographic observations are
independent.

The payload must distinguish:

- `exact`: all eligible centers evaluated; and
- `monte_carlo`: a sampled approximation, with draw count and estimated Monte Carlo error.

## 5. Summary statistics and interpretation

For the weighted reference counts, calculate:

- median;
- 25th and 75th percentiles;
- 10th and 90th percentiles;
- share strictly below the target count;
- share equal to the target count;
- share strictly above the target count; and
- optional midrank percentile: `below_share + 0.5 × equal_share`.

The three shares are preferable to a bare percentile because incident counts contain many
ties. They also avoid implying more precision than the finite count distribution contains.

### Example

Suppose the target has 12 reported incidents within 250 m under the selected filters. The
overlap-weighted MCPP reference distribution has a median of 8, an interquartile range of 4–15,
and these shares:

```text
68% of comparison circles had fewer reports
 7% had the same number
25% had more reports
```

Recommended display copy:

> 12 reported incidents were recorded within 250 m. Among eligible street-centered circles
> in the selected MCPP context, the median was 8 and the middle 50% ranged from 4 to 15. Of
> those comparison circles, 68% had fewer reports, 7% had the same number, and 25% had more.

Acceptable compact table:

| Reference | Target | Median | Middle 50% | Fewer / same / more |
|---|---:|---:|---:|---:|
| MCPP mixture | 12 | 8 | 4–15 | 68% / 7% / 25% |
| Sector | 12 | 10 | 6–18 | 57% / 5% / 38% |
| City | 12 | 7 | 3–16 | 71% / 6% / 23% |

Required interpretation:

> This describes reported-incident counts around eligible comparison locations. It does not
> measure personal risk or label a location safe or unsafe.

### Language to avoid

Do not use:

- "expected crime" or "crime that should occur";
- "risk percentile";
- "safer," "more dangerous," "good," or "bad";
- "significantly higher/lower" unless a separate, valid inferential procedure is implemented;
  or
- claims that a selected person was exposed to or present at any incident.

## 6. Why the first version should not report a p-value

The proposed result is an empirical position within a chosen reference population. It is not,
by itself, a null-hypothesis test.

Three facts matter:

1. The user-selected location is usually not a random draw from the reference frame, so the
   exchangeability needed for a conventional randomization p-value is not established.
2. Nearby equal-radius circles overlap and their counts are spatially autocorrelated. Treating
   them as independent observations would overstate precision.
3. A user can explore many radii, layers, offense filters, and date windows. Reporting the
   smallest apparent tail probability after those choices would create an uncorrected
   multiple-testing problem.

None of these prevent a descriptive empirical distribution. They do prevent converting
`share_below` into a confirmatory probability statement. If a future product requires formal
inference, it needs a written null model, an exchangeability argument, and calibration across
the entire radius/filter search—not merely a new label on the descriptive percentile.

## 7. Adequacy, radius, and fallbacks

Each geography result includes an adequacy status. V1 requires at least **100 unique eligible
centers** and, for MCPP/sector, at least **80% target-circle polygon coverage**. City context
uses the complete city frame and has coverage 1 by construction. A result that fails a floor
is emitted as unavailable with null distribution statistics; the next adequate rung becomes
the primary display. These thresholds are explicit product rules and should be recalibrated
with review data rather than treated as literature-derived constants.

At minimum, adequacy must consider:

- number of eligible centers;
- share of the target circle covered by the reference polygons;
- missing or invalid incident coordinates;
- spread of the reference-count distribution;
- number and concentration of geography components in an overlap mixture;
- Monte Carlo precision when sampling is used; and
- whether preprocessing exclusions leave a representative street frame.

Useful diagnostics include:

```text
effective_geographies = 1 / Σ w_g²
covered_area_share    = area(B ∩ union(reference polygons)) / area(B)
reference_spread      = p90(counts) − p10(counts)
```

The response ladder is:

1. Return the overlap-weighted MCPP result when adequate.
2. Otherwise promote the sector result and explain why MCPP is unavailable.
3. Otherwise promote the city result.
4. If even the city frame or incident coordinates are inadequate, return the target count
   without a comparative claim.

At larger radii the circles will overlap more and the local distribution may lose contrast.
That is a diagnostic outcome, not permission to invent a uniform comparator. Sector and city
results should remain available, and the UI may de-emphasize a low-contrast MCPP result.

## 8. Validation record and follow-up plan

Automated validation currently covers the computational contract below. Sampling-frame
sensitivity and external review remain follow-up research obligations rather than hidden
claims of validation.

### 8.1 Data and computation

- The target count is taken from the detailed Analyze calculation under the same layer, date
  range,
  radius, and filter.
- The same center set is reused when only the incident filter changes.
- Exact and sampled distributions agree within the declared Monte Carlo error.
- Repeated runs and CSV exports are deterministic for the same analysis inputs.
- Weighted quantiles and fewer/equal/more shares are calculated from the same reference counts.

The unit and API contract coverage is in `tests/test_reference_circles.py`,
`tests/test_dashboard_neighborhood_api.py`, `tests/test_analysis_csv.py`, and the
`ReferenceCirclePlot` frontend tests.

### 8.2 Sampling-frame sensitivity

Run a representative location set against street-segment, address-point, and parcel frames.
Document locations where the interpretation changes materially. If the chosen frame produces
systematic artifacts by land use or street geometry, revise the frame rather than hiding the
sensitivity.

### 8.3 Boundary continuity

Test locations on both sides of MCPP and sector boundaries at every supported radius. Small
movements of the target should change overlap weights smoothly rather than cause a
single-polygon cliff. Explicitly test overlapping MCPP polygons and uncovered target-circle
area.

### 8.4 Scale sensitivity

For the same locations and filters, run 250, 500, 750, and 1000 m circles. Measure:

- how target counts and reference distributions change;
- when MCPP mixtures become diffuse;
- when local reference spread collapses;
- whether sector or city becomes the more interpretable frame; and
- whether a radius cutoff is empirically warranted.

### 8.5 Known-pattern simulations

Synthetic maps are appropriate for testing method behavior, even though they are not a model
of Seattle:

- a flat field should not create systematic extremes;
- a concentrated hotspot field should place hotspot-centered circles toward the upper tail;
- a smooth boundary gradient should not produce a discontinuity solely because the MCPP label
  changes; and
- moving or filtering incident points must not change the reference-center frame.

### 8.6 Review

Before launch, review the method and user-facing copy with:

- a spatial statistician or quantitative criminologist;
- Seattle community users who understand what question the comparison needs to answer; and
- a product-ethics review enforcing CompCat's reported-context invariant.

## 10. Literature basis and limits

The proposal combines established ideas, but the exact overlap-weighted MCPP mixture is a new
product-specific design and must be described that way.

| Source | What it supports here | What it does not establish |
|---|---|---|
| Besag & Diggle (1977) | Monte Carlo/randomization methods are legitimate tools for spatial-pattern analysis when their null and sampling procedure are explicit. | This particular reference population or an MCPP weighting rule. |
| Kulldorff (1997) | Moving circular windows across geography is an established spatial-statistical construction. | Treating the selected place's empirical rank as a scan-statistic p-value. |
| Andresen (2009, 2016) | Crime-specific, nonparametric spatial comparison can preserve observed clustering instead of asking whether human activity follows a uniform pattern. | The exact fixed-map, random-center estimand proposed here. |
| Weisburd et al. (2004) | Street segments are a meaningful micro-place unit for Seattle crime analysis, and crime varies substantially between them. | That segment midpoints perfectly represent residents, businesses, or visits. |
| Hipp & Boessen (2013) | Overlapping, radius-based local contexts and explicit scale sensitivity can be more informative than assuming fixed non-overlapping neighborhoods. | A universal best radius or automatic city fallback. |

The defensible claim is therefore:

> The method is a descriptive empirical reference comparison built from established
> nonparametric spatial, circular-window, and crime-at-place traditions.

The indefensible claim would be:

> The literature has already validated this exact MCPP-weighted statistic as a probability of
> crime or personal risk.
